# 最新提示词编辑功能验证

日期：2026-11-11。开发与自动化测试基线：Harness `0.2.1-rc.5`。

## 使用方式

最新一条用户消息的气泡操作栏中，在原生「复制」旁显示「修改」。输入框旁
不再显示修改入口。点击后，Host 立即中断当前 Agent 和其所属
子 Agent，保留并暂停待处理输入，等待停止完成后再显示编辑器。修改后点击
「重新发送」或按 Ctrl/Cmd+Enter；普通 Enter 换行，中文输入法确认不触发发送。
取消修改后，原会话保持停止，原输入框中的未发送草稿保持原样。

重新发送创建同项目下的修订子会话，沿用原提示词之前的真实模型上下文和原
附件。旧提示词及其回复保留在原会话，不进入新一轮的模型上下文。新分支
接入既有会话树和左侧内联分支菜单。

最新消息若仍在原生队列中，界面引导使用原生队列编辑，避免误修改上一条
已执行的提示词。多端更新造成过期编辑时拒绝提交，需要重新打开编辑器。

- 四个发布包的导出、依赖、打包内容检查。

  保持通过。

新增回归覆盖立即取消和等待静止、递归停止所属任务且不影响无关会话、原
历史和附件保留、首条提示词、历史树游标与真实模型上下文、原生选择路径、

气泡入口另覆盖复制按钮相邻且仍可用、消息重挂载、同会话多视图隔离、
切换会话、权限、流式输出不扫描消息列表，以及失败重试时保留原气泡目标。
并发编辑同一会话时，各调用单独核对消息节点，拒绝旧气泡请求。

Host 取消测试使用真实 Session / AgentRegistry 与 Agent 桩；取消信号及保留
队列的行为另核对了官方 Agent driver 实现和相应测试。未调用真实模型。

## 本地客户端实装验证

已在 `/Applications/DeepSeek Harness.app`（`0.2.2-rc.1`）的实际 desktop profile
中安装并启用 `0.7.5-local.3`，三个实现组件均运行中。实际安装包的构建内容
与本次源码一致。

实装发现 Typert 对可选位置参数也检查调用参数个数；客户端始终显式传递
第二个参数。未指定气泡时传 `undefined`；新入口传递气泡对应的 `nodeId`。
官方 rc.5 Gateway 冒烟确认原单参数调用在传输前报错，传 `undefined` 时
正确省略可选字段；桌面重启后携带消息节点的调用也成功。完整验证再次通过。

已在真实客户端确认「修改」只出现在最新用户气泡的「复制」旁，输入框旁
不再显示旧入口；点击后成功读取该消息并打开编辑器，显示「取消修改」和
「重新发送」。客户端保留在编辑界面供用户查看。本地安装前已备份 desktop
profile 配置；未发布 npm 包。

更新包含新 RPC 的插件后，必须完整重启客户端 Host。实装期间热加载新版
代码时，后台仍缓存旧 Typert manifest，曾以 SRC 参数推导拒绝消息节点参数；
完整重启后使用新严格契约，同一气泡请求成功。仅刷新插件页面不足以刷新
这份进程缓存。

实装验证没有重新发送提示词，也没有调用真实模型。运行中中断和重新发送的
完整真实模型端到端流程仍未执行；相关行为由上述自动化测试覆盖。
